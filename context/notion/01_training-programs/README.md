## プログラムの共通フォーマット

4つのプログラム（PPL／UPPER-LOWER／PPL×U-L／全身法）はすべて同じ表形式:

| 列 | 意味 | 値の例 |
|---|---|---|
| SESSION MOVEMENTS | 種目名（自由記述。補足を括弧で付けることが多い） | `S/A ケーブルプルダウン（広背筋）` |
| SETS | セット数 | `2`, `3`, `1-2`（範囲もある） |
| REPS | 目標レップ範囲 | `6-9`, `4-8`, `5-8`, `4-6`, `AMRAP` |
| フォーム解説動画 | 動画へのリンク／メンション（省略表示で中身は取得不可） | `サムトレ動…` |
| RIR | Reps In Reserve（余力レップ数） | ほぼ全部 `0`（限界まで） |
| インターバル(分) | セット間休憩 | `1-2`, `2-3`, `3-5`（空欄もある） |

構造は **プログラム → セッション（A週／B週で色分け） → 種目（セット数・レップ範囲・RIR・休憩）**。

## プラグイン設計の観点でのメモ

- **実際の記録データ（日付×重量×回数）はNotionに残っていない。** 「筋トレログ（入力用）」「トレーニング記録」は中身のないDBの埋め込みだけで、ほかの場所を検索しても重量・回数の記録は見つからなかった。Notionにあるのは「計画（メニュー）」と「種目ライブラリー」で、「実績ログ」はない。
- 種目名の表記ゆれが多い（例: `DB ルーマニアンデットリフト` / `（DBorバーベル/スミス）ルーマニアンデッドリフト` / `SLDL`、`アダクター` / `マシンアダクター`、`HS 45°レッグプレス` / `45°レッグプレス`）。プラグイン側では「種目マスター＋別名（エイリアス）」を持つと集計しやすい。
- 「マシンorDB」「スミスマシンorDB」「T-BARロウorDBロウ」のように**器具を選ぶ種目**がある。記録時にどちらを使ったか残せるとよい。
- 略語: `S/A`＝シングルアーム（片手）、`DB`＝ダンベル、`HS`＝ハンマーストレングス（マシン）、`SLDL`＝スティフレッグデッドリフト、`AMRAP`＝できる回数まで。
- 片側種目（ワンレッグ、S/A）がある → 左右別の記録が要るかは要検討。
- どれが「今やっているプログラム」かはNotionからは断定できない（最終編集が最も新しいのはPPL（三分割））。
