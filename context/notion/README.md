## プラグイン設計に効く要点

1. **Notionにあるのは「計画」と「種目一覧」だけで、「実績ログ」はない。**
   「筋トレログ（入力用）」「トレーニング記録」はどちらも中身のないDBの埋め込みで、ワークスペース全体を検索しても日付×重量×回数の記録は見つからなかった。→ プラグインが最初の実績ログ置き場になる（過去データの移行はほぼ不要）。
2. **メニューの型ははっきりしている。**
   プログラム → セッション（A週／B週） → 種目 × `SETS` / `REPS範囲` / `RIR` / `インターバル(分)`。REPSは `6-9` のような範囲や `AMRAP`、RIRはほぼ `0`。詳細は [01_training-programs/README.md](01_training-programs/README.md)。
3. **種目名がそろっていない。**
   プログラム表の種目名と、ライブラリーの種目名が1対1で対応していない（例: `HS 45°レッグプレス` / `45°レッグプレス`、`DB ルーマニアンデットリフト` / `ルーマニアンデッドリフト`、`マシンアブクランチ`・`ハンギングレッグレイズ` はライブラリーにない）。ライブラリー内でも種目名と動画ファイル名が14件ずれている。→ **種目マスター＋別名（エイリアス）** を持つ設計が必要そう。
4. **器具を選べる種目・片側種目がある。**
   `マシンorDB`、`スミスマシンorDB` などは記録時に器具を残したい。`S/A`（片手）・`ワンレッグ` は左右別の記録が要るか検討。
5. **コンディション管理はテンプレートのままで、ほぼ使われていない。**
   週次レポートに2週分の数値（W06・W07。自分で測った値かテンプレートのサンプルかは不明）、身体計測は項目定義のみ、目標や食事プランは空欄。日次トラッキングのDBは削除済みか権限外（404）。ただし **記録したい項目の候補**（体重・カロリー・PFC・睡眠・歩数・水分・空腹度・ストレス、身体8部位のサイズ）は分かる。

## 取得できなかったもの（Notionで直接確認が必要）

| 対象 | 状況 |
|---|---|
| 「要確認：トレーニングプラン解説」のブックマーク2件 | リンク先URLを取得できない。プランの意図・採用理由・代用種目が載っていそう |
| 全身法の「注意点」・ミニカット冒頭のブックマーク | 同上 |
| PPL／UPPER-LOWER末尾の埋め込みブロック | 外部サービスの埋め込みで中身を取得できない |
| プログラム表の「フォーム解説動画」列 | `サムトレ動…` のような省略表示のみ |
| 日々の記録（日次トラッキング） | 404。削除済みか、連携の権限外 |
| 筋トレログ（入力用）／トレーニング記録 | DBの埋め込みだけで、データの参照先がない |
| PUSHカテゴリの Google Drive ブックマーク | リンク先URLを取得できない |

## 書き出しのルール

- 各ファイルの先頭に `notion_url` / `notion_path` / `notion_last_edited` / `fetched_at` を付けている。
- 種目名・数値・本文はNotionの表記のまま。補足や推測は `> [!note] 書き出しメモ` に分けて書いた。
- Notionのファイル（画像・動画）の署名付きURLは5分で失効するため保存していない。画像・動画もダウンロードしていない（プログラムページの画像は装飾用の写真だった）。
- Notionの更新を取り込みたいときは、この索引の `notion_url` から取り直す。
