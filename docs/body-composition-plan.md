## 0. 状態

2026-10-25 にフェーズ 1〜8 を実装した（`npm run check` 通過。隔離した Obsidian で、スマホ幅・PC 幅、ダーク・ライトを確かめた）。残りはユーザーによる目視と iPhone での確認。

実装で決めたこと・計画から変えたこと:
- 保存先は data.json の既定を「種目フォルダの隣の `body-composition`」にした（パッケージの保存先と同じ決め方。初めてオンにしたときに決めるのではなく、読み込むときに決まる）。
- `時刻` は引用符が無くても読む（YAML 1.1 の 60 進数（07:09 → 429）にも対応）。プラグインが書くときの引用符は Obsidian の `stringifyYaml` 任せ。
- グラフの横軸はログと同じく、期間の中の最初と最後の測定の間（日付の間隔どおり）。期間は最後の測定の日から数える。
- グラフの点をもう一度押すと、その測定を見る（‹ › と同じ）。
- その測定に値の無い丸（「—」）は、目標があっても縁を出さない。
- 設定の説明（項目の一覧）は、設定ノートを読んだ・変えたときに作り直す（宣言的な設定は定義を作ったときの値のままになるため）。
- （0.1.25 の不具合）起動時の保存先の確かめが vault 全体から「名前が日付で数字のプロパティがあるノート」を体組成と数え、TaskChute の分析ノート 574 件を「体組成の保存先へ移す」と聞いていた。体組成は vault 全体からは探さないようにした（上の「保存先」）。

## 1. 背景と目的

- 体重・体脂肪率・筋肉量などの体組成を記録し、推移と、自分で決めた目標までの差を見られるようにする。
- 測り方・データの入れ方は人によって違う（体組成計のアプリから自動で取る人、手で入れる人、体重だけの人）。プラグインは「vault にこの形のノートがあれば読む」という形だけを決め、特定の機器・アプリの形式は読まない。自動で取る人は、その仕組みの側でこの形のノートを書く（§9）。
- 体組成を記録しない人も多いので、既定はオフ。オンにした人にだけページを出す。

### 決めたこと（ユーザー確認済み・2026-10-25）

| 項目 | 決めたこと |
|---|---|
| 置き場所 | ログのタブではなく、メニュー（☰）の別のページ「体組成」。設定「体組成を記録する」をオンにした人にだけ出す |
| 項目名 | 日本語。ノートのプロパティ名がそのまま画面の項目名 |
| 全身の画面 | TANITA の画面に寄せる。値は丸を並べ、押すとその段のすぐ下にグラフ |
| グラフの期間 | 1か月・3か月・半年・1年・すべて。最初は 1か月 |
| 部位別 | 最初の版に入れる（人の形の周りに 体幹部・左右の腕・左右の脚） |
| 目標 | 値を決めると、今の値から「あと 1.3 kg 増」。タブ「目標」に一覧。全身の項目だけ（部位の項目には決めない） |
| 丸の縁 | 目標がある項目だけ、目標までの進み具合 |
| 増やす目標と減らす目標 | 青・▲・「増」／橙・▼・「減」。バーは数の小さいほうが左で、減らす目標は左へ伸びる。丸の縁は増やす目標は時計回り、減らす目標は反時計回り |
| 出さないもの | TANITA の評価（標準・少ない）・標準範囲・体型マップ・増えた／減ったの色分け。測った値と、その差と、目標までの差だけ（ログと同じく、アドバイスや判定は出さない） |

## 2. 用語

| 用語 | 意味 |
|---|---|
| 測定 | 1 回の測定。1 日に 1 つ |
| 体組成のノート | 1 測定 1 ノート（§3.1） |
| 項目 | 体重・体脂肪率など。名前はノートのプロパティ名 |
| 全身の項目／部位の項目 | 部位の項目は「左腕 筋肉量」のように部位と項目を半角スペースでつないだもの。それ以外は全身の項目 |
| 項目の一覧 | 丸に出す全身の項目と、その並び・単位。設定ノートに書く |
| 目標 | 全身の項目に決める値。決めた日を進み具合の起点にする |

## 3. データ設計

### 3.1 体組成のノート（ファイル形式。README にも書く）

`{bodyFolder}/YYYY-MM-DD.md`（例: `Fitness/body-composition/2026-10-22.md`）

```yaml
---
時刻: "07:11"
体重: 66.7
体脂肪率: 18.5
筋肉量: 51.2
内臓脂肪レベル: 7
左腕 筋肉量: 2.9
右腕 筋肉量: 2.9
---
（本文は自由。プラグインは触らない）
```

- **読むノート**: 保存先の中（サブフォルダも）の、名前が日付（`YYYY-MM-DD`）のノートだけ。同じフォルダのほかのノート（自動取得が書く一覧のノートなど）は読まない。日ノートのタグ（`fitness-log`）があるノートも読まない（保存先を誤って同じにしたとき）。
- **1 日 1 ノート**。同じ日にもう一度測ったら書き換える。手で入れたときは、入れた項目だけを書き換えてほかは残す。
- **値は数字だけ**。プロパティの名前が項目名。数字でない値（「標準」など）は読まない（消しもしない）。
- `時刻` は任意（`HH:mm`。引用符は無くても読める）。
- **部位の項目**は「部位 + 半角スペース + 項目」。部位は 体幹部・左腕・右腕・左脚・右脚 の 5 つ（固定）。
- **単位は書かない**（項目の一覧が持つ）。重さ（単位 kg）の項目は kg で書き、表示と入力は設定「重量の単位」に合わせる（セットの重量と同じ）。
- 測っていない項目は書かない。
- 読まないキー: `時刻`・`tags`・`aliases`・`cssclasses`・`fitness_` で始まるもの。

日ノートに入れない理由: 測る日と筋トレの日は別で、毎週決まった日に測る人は筋トレしない日にも日ノートができてしまう。1 つのノートに表でまとめない理由: 項目が 60 を超えると表が読めず、PC と iPhone で同じノートを書くと Sync でぶつかる。

### 3.2 設定ノートに足すキー（`Fitness Log 設定.md`）

```yaml
body_composition: true     # 「体組成を記録する」。無ければオフ
body_items:                # 丸に出す全身の項目と、その並び・単位。無ければ既定（体重・体脂肪率・筋肉量）
  - name: 体重
    unit: kg
  - name: 体脂肪率
    unit: "%"
  - name: 筋肉量
    unit: kg
body_goals:                # 目標。全身の項目だけ
  - name: 体重
    target: 68.0
    since: 2026-07-02      # 決めた日（進み具合の起点）
```

- プラグインの設定は端末間で同期しないので、PC と iPhone でそろえたいものはこのノートに書く。ノートが無ければ、最初に変えたときに作る（カテゴリなどの一覧と同じ）。
- 以前の版は `processFrontMatter` で一覧のキーだけを書き換えるので、このキーは消えない。

### 3.3 data.json

- `settings.bodyFolder`（体組成の保存先）。ほかの保存先と同じく端末ごと。既定は種目フォルダの隣の `body-composition`（例: 種目が `Fitness/exercise` なら `Fitness/body-composition`。パッケージの保存先と同じ決め方）。
- 測定の値・項目の一覧・目標は data.json に置かない。

### 3.4 知っている項目（`src/lib/body/items.ts`）

項目を足すとき、知っている名前なら単位を最初から入れる。小数の桁は、知っている項目は下の表、知らない項目はノートの値から決める（最大 2 桁）。

| 全身の項目 | 単位 | 小数 | | 部位の項目 | 単位 | 小数 |
|---|---|---|---|---|---|---|
| 体重 | kg | 1 | | 筋肉量 | kg | 1 |
| 体脂肪率 | % | 1 | | 脂肪量 | kg | 1 |
| 筋肉量 | kg | 1 | | 脂肪率 | % | 1 |
| 内臓脂肪レベル | — | 0 | | 筋質点数 | 点 | 0 |
| BMI | — | 1 | | フェーズアングル | — | 1 |
| 基礎代謝量 | kcal | 0 | | | | |
| 体内年齢 | 才 | 0 | | | | |
| 推定骨量・脂肪量・除脂肪量・体水分量・タンパク質量 | kg | 1 | | | | |
| 体水分率 | % | 1 | | | | |
| 筋質点数 | 点 | 0 | | | | |
| SMI | — | 2 | | | | |
| アスリート指数 | — | 0 | | | | |

## 4. 画面設計（見本: `docs/body-composition/mock.html`）

### 4.1 入口

- **設定**: まとまり「体組成」。
  - 「体組成を記録する」（トグル、既定オフ。説明「体重や体脂肪率などの推移を見られるようにします。オンにすると、メニューに「体組成」が出ます。」）。値は設定ノートの `body_composition`。
  - オンのときだけ「体組成の保存先」（フォルダ）と「体組成の項目」（「一覧を編集…」、説明は「体重・体脂肪率・筋肉量 ほか 6 項目」）。
- **メニュー（☰）**: 「ログ」の下に「体組成」（オンのときだけ）。オフにしたら、体組成のページを開いていても今日のページに戻す。
- **コマンド**「体組成を開く」（オンのときだけ出す。`checkCallback`）。

### 4.2 ページの上（3 つのタブで共通）

- 「‹ 10/22 (木) › 📅」（日付の下に時刻）。右に「＋ 測定を記録」。
- ‹ › は測定の間を動く（最新より先には進めない）。どのタブも、今見ている測定の値を出す。
- 📅 は測った日のカレンダー（月曜始まり。測った日に色、今見ている日に輪。押すとその日の測定を見る。測っていない日は押せない）。
- ページを開いたときはいつも最新の測定（週に 1 回などしか測らないので、まず見たいのは最新の記録。前に見ていた測定のままにしない）。最新を見ているあいだに新しい測定が届いたら、そちらを見る。
- タブ: 全身 ／ 部位別 ／ 目標（ログのタブと同じ `.fitness-log-seg`）。
- **まだ測定が無いとき**: 「測定を記録すると、ここに体重や体脂肪率が出ます。」と「＋ 測定を記録」。自動で取り込む人向けに、ノートの形（§3.1）と保存先のフォルダ名も短く出す。

### 4.3 全身

- 項目の一覧の順に丸を並べる。列の数は幅から決める（スマホは 3 列）。
- **丸**: 上に項目名、中に値と単位、下に前回からの差（色は付けない。初めての測定なら「初回」、その測定に無ければ「記録なし」）。
- **丸の縁**: 目標がある項目だけ、目標までの進み具合（§4.6）。目標の無い項目は灰色の縁だけ。
- **押すと、その段のすぐ下にパネル**。開くのは 1 つだけで、もう一度押すと閉じる。開いた丸は薄く色を付け、パネルの上の三角でどの丸かを示す。
- **パネル**:
  - 項目名（単位）。
  - 「前回から」「初回から」と、目標があれば「目標まで」（▲ 1.3 kg 増）。それぞれ下に元の値を小さく。
  - 期間のチップ（1か月・3か月・半年・1年・すべて）。最初は 1か月。ページを開いている間は、ほかの項目を開いても選んだ期間のまま。
  - 折れ線: 横軸は日付の間隔どおり（測った順に等間隔にしない。あいた週があっても詰めない）。線 2px・点 8px、最初と最後の値を書く、なぞる・タップでその日の値。目標があれば目標の値に点線（増やす目標は青、減らす目標は橙）を引き、値の範囲に含める。
  - 「10/22 のノートを開く」「目標を決める」（目標があれば「目標を変える」）。
- 下に「項目を編集」。

### 4.4 部位別

- 項目のチップ: ノートにある部位の項目（筋肉量・脂肪量・脂肪率・筋質点数 …）。
- 人の形の周りに、体幹部（上）・左腕と右腕（中）・左脚と右脚（下）の箱。左腕を画面の左に置く（TANITA と同じ）。箱には値と前回からの差。その測定に無い部位は「—」で、押せない。
- 「左右の差」: 腕・脚それぞれ「左 2.9 ／ 右 2.9 ／ 同じ」「右が 0.3 kg 多い」。
- 箱か人の形の部位を押すと、下にパネル。腕・脚は左と右の 2 本の線（青と緑青。凡例あり。橙は減らす目標の色なので使わない）、体幹部は 1 本。
- 部位の項目が 1 つも無いとき: 「「左腕 筋肉量」のような名前で記録すると、部位ごとに出ます。」

### 4.5 目標

- 目標の一覧（項目の一覧の順）。1 行に:
  - 名前・「今 66.7 kg」・右に「▲ あと 1.3 kg 増」／「▼ あと 1.5 % 減」／「目標に届いています」。
  - バーと、その両端に「7/2 に決めたとき 65.2 kg」と「目標 68.0 kg」（数の小さいほうが左）。
- 行を押すと「目標を変える」（値を変える・「目標を消す」）。下の「＋ 目標を決める」は、項目（全身の項目のうち、まだ目標の無いもの）と値を聞く。
- 目標が無いとき: 「目標の値を決めると、今の値からあとどのくらいかを出します。」と「＋ 目標を決める」。
- 目標を消すのに確認は出さない（モーダルの「目標を消す」をはっきり押したときだけ消える）。

### 4.6 目標までの進み具合（`goalProgress`）

- **起点**: 目標を決めた日（`since`）以前で最後の測定の値。無ければ最初の測定。
- **向き**: 目標 − 起点 の符号（同じなら 目標 − 今）。増やす目標は青・▲・「増」、減らす目標は橙・▼・「減」。
- **進み** = (今 − 起点) ÷ (目標 − 起点) を 0〜1 に収める。目標に届いた（越えた）ら 1 で「目標に届いています」。目標から離れたら 0（空のまま）。
- **バー**は増やす目標なら左から、減らす目標なら右から伸びる。**丸の縁**は 12 時から、増やす目標は時計回り、減らす目標は反時計回り。
- 色だけに頼らない（記号・言葉・向きでも分かる）。青と橙はパッケージの 8 色（色覚の違いで検証済み）の 0 番と 1 番を使う。
- 「今」は今見ている測定。‹ › で戻れば、その時点での差になる。

### 4.7 測定を記録（モーダル）

- 日付（今日）・時刻（今）。項目の一覧の項目ごとの欄（薄い字で前回の値。空欄の項目は記録しない）。
- 「部位別」（たたんでおく）: ノートにある部位の項目 × 5 部位。ノートに部位の項目が無ければ 筋肉量・脂肪率。
- 保存: その日のノートが無ければ作り、あれば入れた項目だけを書き換える。保存したら、その測定を表示する。
- 数字でない入力は「「体重」は数字で入れてください」。1 つも入れていなければ「数値を 1 つ以上入れてください」で保存しない。
- スマホ: 欄は `inputmode="decimal"`（項目が多いのでホイールにはしない。使ってみて決める）。

### 4.8 項目の編集（モーダル）

- 丸に出す項目: ⋮⋮ で並べ替え（`sortable.ts`）・単位を変える・🗑 で外す（ノートの値は消えない。外すだけなので確認は出さない）。
- 「ノートにある項目」: ノートにあって一覧に無い全身の項目。＋ で足す（知っている名前は単位も入る）。
- 「＋ 新しい項目…」: 名前と単位。
- 名前は変えられない。名前はノートのプロパティ名そのものなので、変えると以前の測定とつながらなくなり、自動取得が次に書く名前ともずれる。

## 5. 設計の要点（コード）

- **純粋ロジック** `src/lib/body/`（'obsidian' を import しない。テストを書く）
  - `note.ts`: frontmatter → `BodyMeasurement { date, time: string | null, values: Record<string, number> }`（読まないキー・数字でない値を除く）。手で入れた値を frontmatter に足す `applyMeasurement(fm, values, time)`。ノートの名前が日付かどうか。
  - `items.ts`: 知っている項目（単位・小数、§3.4）。`splitPartKey('左腕 筋肉量') → { part: '左腕', measure: '筋肉量' }`。小数の桁の推定。重さの項目の表示単位（kg／lb）。
  - `settings.ts`: 設定ノートの `body_*` の読み書き（`bodySettingsFromFrontmatter` / `applyBodySettingsToFrontmatter`。`lists.ts` と同じ形）。
  - `stats.ts`: 前回・初回・期間で絞った点、`goalProgress`（§4.6）、`balance`（左右の差）、開いた丸の段の最後の位置（列の数から）。
- **データ層** `src/data/body-library.ts`（`BodyLibrary`）
  - 保存先の日付の名前のノートを、metadataCache の frontmatter から読む（本文は読まない）。メタデータの `changed`・vault の `delete`・`rename` で読み直す（debounce）。変わったら `change` を出し、`MainView` が描き直す。
  - `record(date, time, values)`: ノートを作る（`Vault.create`）か、`FileManager.processFrontMatter` で入れた項目だけ書き換える。
  - オフのあいだは読まない（起動を軽く保つ）。
- **設定ノート**: `ListsLibrary` を設定ノート全体の読み書きに広げ、体組成の設定も持つ（`DataStore` に写し `bodySettings`）。`setBodyEnabled`・`setBodyItems`・`setGoal`・`removeGoal`。ほかの端末の変更（Sync）・Properties 欄での編集も今の一覧と同じく読み直す。
- **保存先**: `FitnessLogSettings.bodyFolder`。`FOLDER_KEYS` に足す（ほかの保存先と重ならないか・設定を変えたらノートを移すか聞く・フォルダの名前の変更を追いかける）。
  - 体組成のノートは vault 全体からは探さない（印が無く、ほかのプラグインの日付の名前のノートと見分けられない）。起動時の「ノートの場所の食い違い」調べは体組成を除き、保存先を変えたときだけ、前の保存先の中の体組成のノート（名前が日付で数字の項目がある・日ノートではない）を移すか聞く（`findBodyNotePaths`・`checkBodyFolderMove`）。
  - `migrateFolderNames`（`ログ`・`種目` → 英語）のループは体組成を除く。
  - 最初の設定（`setup-modal.ts`）では聞かない（既定はオフ）。
- **チャート**: `renderSeriesChart`（`src/ui/chart.ts`）に目標の線（`guide: { value, cls, label }`。値の範囲に含める）を足す。期間の絞り込みは呼ぶ側で行う。
- **ページ**: `PageId` に `'body'`。ドロワーはオンのときだけ出す。オフのときに `'body'` を開こうとしたら（保存されたビューの状態など）今日のページにする。アイコンは lucide の `person-standing`（Obsidian に入っているか `setIcon` で確かめる。無ければ `activity`）。
- **丸**: SVG（`createSvg`。`cls` は配列で渡す）。縁は `stroke-dasharray`、反時計回りは上下を反転。
- **文言**は `src/i18n/ja.ts` の `body.*`。

## 7. 実装フェーズ

各フェーズの終わりに `npm run check` を通す。UI のフェーズは `npm run build` の後に `npm run e2e` で、dev-vault のコピー（作りものの体組成のノート入り）を操作して確かめる（スマホ幅 `emulateMobile`・ライト／ダーク・`window.__errs` が空）。commit・リリースは頼まれたときだけ。

### フェーズ 1: 純粋ロジック（`src/lib/body`）
- `note.ts`・`items.ts`・`settings.ts`・`stats.ts` とテスト。
- テスト: 日付の名前のノートだけを読む／数字でない値と読まないキーを除く／`時刻` の有無／部位の項目の分け方（「左腕 筋肉量」「体幹部 脂肪率」、部位でない「左右差」は全身）／手で入れた値の上書き（ほかの項目を残す）／小数の桁／kg と lb／前回・初回（その項目が無い測定を飛ばす）／期間の絞り込み／目標（増やす・減らす・届いた・離れた・起点が無い・起点と目標が同じ）／左右の差／設定ノートの往復（キーが無い・壊れた値）。

### フェーズ 2: データ層
- `BodyLibrary`、設定ノートの体組成の設定、`bodyFolder`、`FOLDER_KEYS` と保存先の確かめ。
- テスト（仮想 vault）: 保存先の日付の名前のノートだけを読み、同じフォルダの一覧のノートは読まない／新しい日にノートを作る・同じ日は入れた項目だけを書き換える／ノートを外から変えたら読み直す／オフのあいだは読まない／設定ノートに体組成のキーを書いても一覧のキーはそのまま（逆も）。

### フェーズ 3: 設定とページの入口
- 設定のまとまり「体組成」・ドロワーの「体組成」・コマンド・まだ測定が無いときのページ。

### フェーズ 4: 全身

### フェーズ 5: 測定を記録・項目の編集

## 9. 自動で取り込む人へ（README にも書く）

- §3.1 の形で、1 回の測定ごとに 1 ノートを体組成の保存先に書く（設定 → 体組成の保存先）。
- 書かないもの: 体組成計の評価（「標準」など）・評価値・左右バランスの文章・体型・目標体型までの差（プラグインは読まない）。
- 部位別の値は「左腕 筋肉量」のように書くと、部位別のページに出る。
- 目標はプラグインの画面から決める（設定ノートに書く）。自動取得の側では書かない。
- 同じ保存先にほかのノート（全部の測定の一覧など）を置いてもよい。プラグインは日付の名前のノートだけを読む。
