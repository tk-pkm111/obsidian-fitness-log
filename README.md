# Fitness Log（Obsidian プラグイン）

筋トレの記録を Obsidian で取るためのプラグイン。ジムでスマホから「開始 → 終了 → 回数」だけで記録でき、記録は vault の Markdown ノート（1 日 1 ノート）に残る。名前・id（`fitness-log`）は仮。

- 設計: [docs/implementation-plan.md](docs/implementation-plan.md)（データ設計・画面設計・フェーズ）、体組成のページ: [docs/body-composition-plan.md](docs/body-composition-plan.md)
- 使い方: [docs/guide/](docs/guide/README.md)（画像つきの使い方。全ページのまとめは [docs/fitness-log-guide.md](docs/fitness-log-guide.md)）
- 開発環境: [docs/harness.md](docs/harness.md)
- 前提資料（Notion から書き出したメニュー・種目）: [context/notion/README.md](context/notion/README.md)
- AI（Claude Code）向けの運用ルール: [CLAUDE.md](CLAUDE.md)

## できること

| 画面 | 内容 |
|---|---|
| 今日 | 筋トレ中は**いまの種目**だけを開き、セットをサブタスクとして並べる（終えたセットの番号・実行中の ■・次のセットの ▶・目標までの残りの薄い行）。終わった種目は 1 行、まだの種目は ▶ だけ。パッケージ名を押すとそのパッケージの編集へ。休憩は最後にセットを終えた種目のすぐ下に、経過・目安・進みのバーで出る（目安を過ぎるとオレンジ。筋トレ中だけ）。回数・重量はワンタップの候補から選べる。ヘッダーは「☰ ／ ‹ 📅 今日 (10/1 木) › ／ ＋」。その日のパッケージ（ルーチンの予定＋追加したもの）は畳んで表示し、**▶ 筋トレを開始**で開始時刻を記録して種目カードを展開。カードは種目名と左の ▶ だけのシンプルな形で、**やった順**に並ぶ（▶ を押した種目は最後にやった種目のすぐ下へ。前にやった種目をもう一度始めると下にもう 1 枚出て、セット番号は続きから）。▶ でタイマー、■ で回数を聞いて記録。終えたセットの重量・回数・開始・終了・休憩は数字を押してその場で直せ、右の吹き出しでセットごとにコメント（感じたこと）を残せる（日ノートの「コメント」列）。セットの行の … （番号の丸からも）で削除、種目を間違えたときは「この種目を今日から外す」で記録ごと外せる（初回だけ「今日は何 kg？」、2 セット目以降は前のセットの重量を引き継ぐ。前回の記録をパッケージ × 種目ごとに初期値とヒントに出す）。その日のパッケージと単発の種目はまとめて 1 日の筋トレで、いちばん下の右の **■ 筋トレを終了** でまとめて終え（パッケージごとの終了は最後のセットの終了。最後にやったものだけ押した時刻）、「今日もお疲れ様でした」とその日のまとめ（時間・種目数・セット数）と「ノートを開く」を表示（**↻ 筋トレを再開**でまとめて再開。今日だけ）。筋トレ中に別のパッケージも始められる。種目名のすぐ右の 📈 で前回までの記録（直近 5 回の重量・回数・セットのコメントと最高のセット。「ログで詳しく見る」でログへ）。パッケージ名の行の 💬 で全体のコメントを 1 件ずつ足す（新しい 2 件だけを 1 行ずつ出し、前のものは「前の N 件」にたたむ。押すとその 1 件を直す・消す）。まだやっていない種目は ⋮⋮ でその日だけ並べ替えられる。休憩タイマー、メモ、セットの修正・削除、過去日の手入力。種目名を押すと種目ノートが開く スマホでは数字（重量・回数・時刻・休憩）を押すと、スクロールで選ぶホイールが開く（「キーボードで入力」もできる） |
| パッケージ | 種目の束（例: PUSH A）。一覧も種目も左の ⋮⋮ をつかんでドラッグで並べ替え。設定で「パッケージのセクションを使う」をオンにすると「背中」「腕」のような区切り（セクション）を入れられ、今日の画面にも見出しとして出る。目標（セット数・回数・休憩）は種目ごとの「詳細設定」に畳んである（今日の画面には出さない。休憩タイマーが目標を超えると色が変わる）。並び替え・複製・削除。パッケージの例（3 分割・2 分割・5 分割・全身）をテンプレートとして追加 種目の × は確認してから外し、目標の設定と位置は覚えておく。外した種目をもう一度追加すると、候補の先頭に出て「以前の設定で戻す（元の位置）／新しく設定する」を選べる。編集の下の「外した種目」（たたむ）で、外した種目とこのパッケージでの記録（最後の日・回数）を見て、「記録」で推移を開く・「戻す」で入れ直せる。詳細設定は「変更を保存」で保存して閉じる。スマホでは目標の数字もホイールで選ぶ |
| 種目 | **1 種目 1 ノート**（`Fitness/exercise/ケーブルYレイズ.md`、初期 66 種目）。カテゴリ・器具・記録のしかた（重量 × 回数／回数のみ／時間のみ／重量 × 時間／距離 × 時間。重量・回数・距離・時間から自分で組み合わせも作れる）・片側・別名・アーカイブは編集画面からノートの frontmatter に保存し、本文にはフォームやコツを自由に書ける。名前を変えるとノートの名前も変わり、旧名を `aliases` に残して過去の記録と繋がる |
| ルーチン | **月のカレンダー**（月曜始まり。各日のパッケージを色付きで、やった＝塗り・予定＝枠・スキップ＝取り消し線）。パッケージ名を押すとその日の画面へ直接飛ぶ（やった日は記録を開いた状態で）。日の空いたところを押すとその日のパッケージと種目の一覧、スキップ／戻す、「この日を開く」。 |
| ルーチン（ルール） | 「毎週 月・木 は PUSH A」「3 日ごと」など。有効／無効、期間。今日の画面やカレンダーで「この日はスキップ」 |
| 体組成 | 設定の「体組成を記録する」をオンにした人だけメニューに出る。開くといつも最新の測定を出し、‹ › とカレンダー（測った日に色。押すとその日の測定）で前の測定を見られる。**全身**: 体重・体脂肪率などの値を丸で並べ、押すとその段の下に前回から・初回から・目標までの差と推移のグラフ（1か月〜すべて。最初は 1か月）。**部位別**: 人の形の周りに体幹部・左右の腕・左右の脚の値と左右の差、押すと左右 2 本の線。**目標**: 決めた値まで「▲ あと 1.3 kg 増」「▼ あと 1.5 % 減」とバー（丸の縁にも進み具合）。「＋ 測定を記録」で手で入れられ、ほかのアプリから自動で取り込むこともできる（下の「体組成のノート」）。体組成計の評価（標準など）は出さない |
| ログ | **パッケージ**: パッケージを選ぶと、その中の種目が今の並び順で、前回のセット・前回比・推移の小さな線・★ 自己ベスト付きで並ぶ（1 回ごとの合計ボリュームの棒も）。種目を押すとそのパッケージの中での推移（推定 1RM・最大重量・ボリューム／回数／時間）と記録の表。「ほかのパッケージと比べる」で別のパッケージの線を点線で重ねられる。パッケージから外した種目も「今の内容に無い種目」に記録が残る。**種目**: 種目を検索して、パッケージごとの線で推移を見る。**月ごと**: 日ごとの一覧。アドバイスは出さず、事実（記録・前回比・自己ベスト）だけを並べる。ログを表で見る Bases ファイルの作成 |

最初の起動では「Fitness Log をはじめる」で、保存するフォルダを 1 つだけ聞く（その中に `ログ` と `種目` を作る。別々のフォルダも選べる。vault に既にノートがあればその場所をそのまま使う）。よく使う種目とパッケージの例を入れるかも選べる。いちばん下に使い方の動画（42 秒、[docs/onboarding-video/](docs/onboarding-video/)）。コマンド「保存先を設定」でやり直せる（動画もここで見直せる）。

画面の切り替えは左上の ☰（左のメニュー）。コマンド: **今日のトレーニングを開く**／**トレーニングログを開く**／**体組成を開く**（体組成を記録するときだけ）／**保存先を設定**／**ログの Bases ファイルを作成**。リボンのダンベルのアイコンでも開ける。

## 記録の形式（日ノート）

記録があった日だけ、`{ログの保存先}/{YYYY-MM-DD}.md` に作る。プラグインが書き換えるのは `%% fitness-log:start %%` 〜 `%% fitness-log:end %%` の間と、frontmatter の集計キーだけ。ブロックの外は自由に書ける。

```markdown
---
tags:
  - fitness-log
date: 2026-10-01
packages:
  - PUSH A
exercises:
  - ケーブルYレイズ
sets: 2
volume_kg: 190
duration_min: 1
---
%% fitness-log:start %%
## PUSH A
- 時間: 18:30:05 – 19:20:12
- コメント: 調子よし

### ケーブルYレイズ
| セット | 重量 (kg) | 回数 | 開始 | 終了 | コメント |
| ---: | ---: | ---: | --- | --- | --- |
| 1 | 10 | 9 | 18:31:05 | 18:31:50 | |
| 2 | 12.5 | 8 | 18:34:10 | 18:34:55 | 右肩注意 |
%% fitness-log:end %%

## 今日のメモ
（ここは自由に書ける）
```

- 「時間」は **筋トレを開始・終了** した時刻（筋トレ中は `18:30:05 –` と終了が空欄）。frontmatter の `duration_min` はこの間の分数。
- 「コメント」（以前の「メモ」も読む）はパッケージ全体のコメントで、1 件 1 行（書いた順）。
- 表を手で直してもよい（保存すると画面に反映される）。読めない形に壊れたときは書き込みを止め、通知からノートを開ける。
- 重量は常に kg で保存する（設定の単位は表示と入力だけ）。空欄は `-`。距離を記録する種目の表にだけ `距離 (km)` の列が付く。
- 単発の種目（どのパッケージにも入らない種目）の記録は `## その他`。「筋トレを終了」したときだけ「時間」を秒まで（`22:09:00 – 22:27:50`）書き、それ以外はセットから分までを計算する。
- 種目・パッケージは名前で書く（AI や人が読める）。名前の照合は本名＋別名で行う。
- パッケージとルーチンは 1 パッケージ 1 ノート（`Fitness/package/PUSH A.md`。種目・目標・区切り・ルーチンを frontmatter に、本文は自由なメモ）が正。種目は種目ノートが正（下記）。どちらも vault の中なので、Obsidian Sync でプラグインの設定（「インストールされているコミュニティプラグイン」）を同期しなくても、端末間でそろう。
- 進行中のセットと設定（保存先・単位など）は端末ごとのプラグインの `data.json` に保存する。

## 種目ノート

```markdown
---
aliases:
  - Yレイズ
tags:
  - fitness-exercise
fitness_id: ex_b19hcx3y
category: プッシュ
equipment: ケーブル
record_type: weight-reps
unilateral: false
archived: false
---
## フォーム
（ここから下は自由に書ける。プラグインは触らない）
```

- ファイル名 = 種目名（`/` などファイル名に使えない文字は全角）。Properties 欄で値を変えても、ファイル名を変えてもプラグインに反映される。
- `fitness_id` はパッケージとの結び付けに使うので消さない（消えたら振り直すが、パッケージから外れる）。
- 種目フォルダに自分でノートを作ると、新しい種目として読み込む（`fitness_id` は自動で振る）。
- `category`・`equipment` は名前をそのまま書く（以前の版の `push` などの英語のキーは、読み込んだときに名前へ書き直す）。`record_type` は記録する項目（`weight`・`reps`・`distance`・`duration`）を `-` でつないだもの。

## 体組成のノート

体組成は 1 回の測定で 1 ノート（`{体組成の保存先}/YYYY-MM-DD.md`。既定は種目フォルダの隣の `body-composition`）。手で入れても、ほかのアプリや自分の自動取得の仕組みから同じ形で書いてもよい。

```markdown
---
時刻: "07:11"
体重: 66.7
体脂肪率: 18.5
筋肉量: 51.2
内臓脂肪レベル: 7
左腕 筋肉量: 2.9
右腕 筋肉量: 2.9
---
（本文は自由。プラグインは触らない）
```

- 読むのは保存先の中の、名前が日付のノートだけ。同じフォルダにほかのノート（全部の測定の一覧など）を置いてもよい。1 日 1 ノートで、同じ日にもう一度記録すると入れた項目だけを書き換える。
- プロパティの名前が項目名、値は数字だけ（「標準」のような文字の値は読まない）。単位は書かない（項目の一覧が持つ）。重さ（kg）の項目は kg で書く（表示と入力は重量の単位に合わせる）。`時刻` は任意。
- 部位別の値は「左腕 筋肉量」のように部位と項目を半角スペースでつなぐ。部位は 体幹部・左腕・右腕・左脚・右脚。
- 測っていない項目は書かない。体組成計の評価・評価値・左右バランスの文章・体型も書かなくてよい（プラグインは読まない）。
- 丸に出す項目と単位・目標・オン／オフは設定ノート（下記の `Fitness Log 設定.md` の `body_items`・`body_goals`・`body_composition`）に書くので、ほかの端末とそろう。目標は画面から決める。

## 種目の選択肢（カテゴリ・器具・記録のしかた）

一覧は vault の設定ノート（種目フォルダの隣の `Fitness Log 設定.md`。タグ `fitness-settings`）に保存するので、ほかの端末とそろう。ノートは最初に一覧を変えたときに作る（それまでは既定の一覧）。種目の編集画面の選ぶ欄の「＋ 新しい…」でその場で足し、「一覧を編集…」（設定の「種目の選択肢」・種目の画面の ✎ からも）で名前の変更・並べ替え・削除ができる。カテゴリ・器具の名前を変える・消すと、使っている種目ノートも書き直す。

## 設定

ログの保存先（既定 `Fitness/log`。日ノートは `Fitness/log/2026-10-01.md`）、種目ノートの保存先（既定 `Fitness/exercise`。以前の既定の名前（`…/ログ`・`…/種目`）のままの vault は、更新後の最初の起動で英語の名前に移す。設定で変えると、設定を閉じるときに今あるノートを新しい保存先へ移すか聞く。vault でフォルダの名前を変えたり移したりしたときは設定が追いかける）、ノート名の形式（moment の書式。`/` でサブフォルダ）、重量の単位（kg／lb）、重量の刻み、休憩タイマーの表示、起動時に今日の画面を開く。「体組成」で体組成を記録するか（オンにすると保存先と項目の行が出る）。「データ」から初期データの再投入（不足分だけ）と Bases ファイルの作成。

## 開発

```bash
npm install
npm run vault:setup        # 開発用 Vault（dev-vault/）に hot-reload を導入
npm run references:fetch   # 公式ドキュメント・公式テンプレートを references/ に取得
npm run dev                # 監視ビルド。dev-vault に自動コピー
```

Obsidian で `dev-vault/` を Vault として開き、コミュニティプラグインを「信頼して有効化」する。以後、ソースを保存すると自動で再読み込みされる。

| コマンド | 内容 |
|---|---|
| `npm run dev` | 監視ビルド + dev-vault へコピー |
| `npm run build` | 本番ビルド（型チェック込み） |
| `npm run check` | 型チェック + Lint + 整形チェック + テスト |
| `npm run test:watch` | テストの監視実行 |
| `npm run format` | 整形 |
| `npm run vault:dummy -- --folder Fitness-dummy` | dev-vault にダミーの日ノート（PPL を回した 300 日分）を作る。チャートと性能の確認用 |
| `npm run e2e -- launch` など | 隔離した Obsidian を起動して画面を自動操作する（[docs/harness.md](docs/harness.md) の「E2E」） |

## 構成

```
src/main.ts          ライフサイクル（登録・onLayoutReady・外部変更の再読込）
src/commands.ts      コマンド
src/settings.ts      設定タブ（宣言的。data.json の settings に読み書き）
src/services.ts      画面とコマンドに渡すサービスのまとまり
src/i18n/            UI 文言（t('key')）
src/lib/             Obsidian 非依存の純粋ロジック（vitest でテスト）
  model/             型・初期データ・名前解決・data.json の正規化・カタログ操作
  log/               日ノート ⇄ DayLog、集計、変更操作、Bases
  history/           前回値の引き継ぎ・統計・パッケージ別のログ・チャートの座標・月ごとの一覧
  schedule/          ルーチンの判定
  today/             今日ページのモデル
src/data/            data.json（DataStore）・日ノート（LogRepository）・履歴索引（LogIndex）・種目ノート（ExerciseLibrary）・パッケージノート（PackageLibrary）
src/session/         開始・終了・修正の手順（SessionController）
src/ui/              メインビュー・各ページ・モーダル・チャート
tests/               vitest（obsidian は tests/__mocks__/、vault は tests/helpers/fake-app.ts の仮想 vault）
scripts/             dev-vault の準備・参照資料の取得・ダミーデータ・E2E
```

要件: Obsidian 1.13.0 以上。デスクトップ・モバイル対応（Node.js / Electron API は使わない）。

通信: はじめの設定で使い方の動画の再生を押したときだけ、このリポジトリの動画（約 3.5 MB）を [jsDelivr](https://www.jsdelivr.com/)（GitHub のファイルを配信する CDN）から読み込む。それ以外の通信はしない（記録・vault の内容はどこにも送らない）。
